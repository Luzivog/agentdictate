# Repository audit, 5 September 2026

The audit started from `90a1c8b246ccf003484e69620cc6a8ee2e7a9453` on a clean
`main` checkout. Changes focus on replacement processing and repeatable developer
feedback. This is a focused audit, not a claim that every module is free of dead code.

## Changes

- Cache the constant Unicode word-character regex and initialize it only when a
  whole-word match needs a boundary check. Previously every call compiled it,
  including calls with no active rules.
- Stream accepted replacement matches into the result instead of allocating a
  vector of all match offsets. Rule order, Unicode boundaries, literal replacement
  values, and applied counts are unchanged.
- Delete runtime's duplicate ASCII word-count implementation and direct `regex`
  dependency. Both history persistence and external imports call the existing core
  function with the identical regex.
- Remove the theme test that restated palette and spacing constants. Keep the
  rendered UI, layout, recovery, migration, and protocol tests. Add replacement
  coverage for Unicode neighbors, literal dollar signs and backslashes, cascading
  rules, deletion, and nonoverlapping matches.
- Add `scripts/dev.sh` for setup inspection, focused tests, and benchmarks. Checks
  preserve commands, revision, output, timing, and exit status. A filter matching
  zero passing tests fails. The desktop harness enables headless GPUI test support.
- Add shell fixtures that verify runner argument boundaries, exit-code propagation,
  saved logs, and zero-test rejection. Include them in the existing full gate.
- Document main-only coordination, setup, debugging, benchmarks, headless feedback,
  live verification limits, and installation in [the development workflow](DEVELOPMENT.md).

## Measurements

Command: `cargo bench --locked -p agentdictate-core --bench replacements`.
Host: AMD Ryzen 5 PRO 8540U, Linux x86_64, Rust 1.95.0. The benchmark uses the
locked dependencies and release profile. Before and after runs used the same
fixture and host without competing Rust builds. Values are median nanoseconds
per call from nine calibrated batches. See the benchmark source and development
guide for calibration and timed work.

| Case | Before, ns | After, ns | Time saved per call |
| --- | ---: | ---: | ---: |
| No rules, 30 bytes | 167,338 | 21 | 0.167 ms |
| Disabled rule, 30 bytes | 166,497 | 23 | 0.166 ms |
| One rule, no match | 249,128 | 43,201 | 0.206 ms |
| One rule, 30 bytes | 228,594 | 44,928 | 0.184 ms |
| One rule, 30 KB | 571,449 | 363,732 | 0.208 ms |

The short fixture is 5.09 times faster; the long fixture is 1.57 times faster.
The absolute savings are fractions of a millisecond. These measurements cover
warmed sequential replacement processing and do not establish end-to-end dictation
latency, cold-start latency, or concurrent throughput.

## Verification and remaining gaps

- Focused core integration tests: 39 passed. Runtime integration tests: 61 passed.
  Headless rendered UI interaction tests: 35 passed.
- Clippy passed for both changed production crates with warnings denied.
- The single `./run-tests.sh` run passed: 402 Rust tests passed, one live subscription
  test remained ignored, shell feedback fixtures passed, native-readiness packaging
  fixtures passed, and `cargo deny` passed. Cargo deny reported duplicate-version
  warnings for `getrandom`, `hashbrown`, `syn`, and `windows-sys`.
- An independent read-only agent reviewed the diff and benchmark receipts. It found
  no functional defects and caught a benchmark-documentation ambiguity, now fixed.
- `shellcheck` and pkg-config metadata for xkbcommon, xkbcommon-x11, fontconfig,
  and freetype2 were unavailable. Focused builds and the full gate linked on this
  host with the existing runtime-library fallback. Clean-host packaging was not tested.
- Real microphone capture, provider access, compositor visibility, and insertion
  into another application were not exercised. Native tests that return early when
  device access is absent do not prove access solely by reporting a passing test.
- Broader startup, history-query, and network changes need their own measurements
  and acceptance checks. They were left outside this change.
